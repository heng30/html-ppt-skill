起点

标准二分搜索 · Rust

算法正确，编译优化，然而硬件层面存在隐藏的性能杀手。

Rust 代码 
while min_idx < max_idx {
    let middle = min_idx + ((max_idx - min_idx) / 2);
    if less_than(boundaries[middle], value) {
        min_idx = middle + 1;   // 分支 A
    } else {
        max_idx = middle;       // 分支 B
    }
}
⚠️ 问题：数据均匀分布 → 每次比较方向完全随机 → CPU 分支预测器失效。

优化 #1

无分支执行

固定迭代次数，使用条件移动指令替代分支。

Rust 
let n_iterations = (size as f64).log2().ceil() as usize;
for _ in 0..n_iterations {
    left = select_unpredictable(
        less_than(boundaries[middle], value),
        middle, left
    );
}
✅ 效果：分支误预测率降至 0%，IPC 飙升至 4.0，耗时降至 13,198 µs（3.5× 加速）。

优化 #2

消除边界检查 + 预计算

Rust 
let halves = precompute_halves(); // 预计算
for half in &halves {
    let middle = left + half;
    left = select_unpredictable(
        less_than(unsafe { *boundaries.get_unchecked(middle) }, value),
        middle, left
    );
}
分支降至 8M，指令降至 121M，耗时 10,037 µs（再快 24%）。
优化 #3

自动向量化与 SIMD

重组循环：外层 halves，内层 chunk (16个值)。编译器自动生成 SIMD 指令。

Rust 
for chunk in arr.chunks(16) {
    for half in &halves {
        for (i, value) in chunk.iter().enumerate() {
            lefts[i] = select_unpredictable(/*...*/);
        }
    }
}
启用 x86-64-v3 目标，指令降至 99.9M，耗时 7,106 µs。

核心收获 · 你也可以做到

🧠 理解 CPU

  • 分支预测失败代价巨大
  • IPC 是效率标尺
  • 内存延迟 > 计算延迟

🔧 优化策略

  • 消除不可预测分支
  • 减少重复计算
  • 利用 SIMD 并行
