03 · 类型系统 / Type System Rust Compiler · 2026

两笔最大的债，同年进入收尾

这两件事加起来，等于把类型系统的一大块重写了一遍。

T1
下一代 trait solver ≈ 10 年 · 多种形态，反复重来

修掉一批健全性 bug，同时一次性解开它挡住的一长串问题，包括 async Rust 里的大麻烦，和各种 impl Trait 的限制。

一笔技术债清掉之后，一批真正懂类型系统的人也腾出手来，可以去做新东西了。

T2
Polonius 借用检查器 长期项目 · 同样是多年的等待

新的借用检查器实现，让更多代码能编译通过，并连带解锁一批相关特性，包括（希望有一天）内部引用。

对编译器本身的影响没有新 solver 那么大，但仍然是件大事。

两条线在同一时期收尾，2026 才显得像是「突然」发生了很多事。 next solver / polonius
04 · 性能 / Perf Rust Compiler · 2026

停滞一两年之后，同时开花

不是某一项大突破，是四件事叠在一起：新人进来、老人腾出手、工具变好、架构清理解锁新机会。

PF
并行前端
@SparrowLi 重启了这项多年停摆的工作，@petrochenkov 现在驱动它。设计几乎没人满意，但看不到更好的替代，只能一条条磨完。
接近稳定
ME
MIR 层面的 move 消除
@Amanieu 提出。消掉 LLVM 优化不掉的拷贝。Rust 比 C/C++ 产生更多 move，所以这件事对 Rust 特别值。编译期与运行期同时变快。
编译期 + 运行期
PM
Polymorphization
第三次实验，这次是 Swift 风格：把泛型参数的 layout 当参数传。有运行时开销，可开关。@camelid 驱动。
实验阶段
CC
check 与 build 共享缓存
@blyxyas 的项目目标。目标本身更大，但共享产物是最好认的那个结果，想要了很多年。
进行中
TM
target 目录瘦身
no-embed-metadata 默认开启，target 目录小 5–30%；新的 build-dir 布局带来细粒度锁与跨 workspace 缓存。
−5~30%
为什么是现在一个想法会在几个人脑子里同时转。人们被彼此的 PR 启发，去做相关的事。
回归管理把 tree ops 和性能分诊接起来：合并的人顺手看这次合并的性能影响，响应时间因此缩短。
代价解释结果、诊断回归，有时只需要有人多说几句，而那个人每天看这些数字已经看了很多年。
Conway 定律依然是定律：组织结构会从技术结果里透出来。 "Turns out that Conway's law is still a law."
05 · 性能 / LLVM Rust Compiler · 2026

LLVM 23：第一次「几乎全是好的」

LLVM 长期是 rustc 性能的拖累项。转折点在 @nikic 那篇《Make LLVM fast again》，LLVM 开始像 rustc 一样追踪自己的性能。

LLVM 10 · 长期拖累
一次升级带回 10%
从这之后，rustc 的 LLVM 升级基本是「坏多好少」，然后慢慢变成「少坏一些」。
LLVM 22 · 好坏参半
icount 全绿，wall time 全红
基准好看，实际墙钟时间几乎处处变慢。这一年的结论是「还不行」。
LLVM 23 · 几乎全正向
两头都好了
新优化（在 bootstrap 时也在优化编译器本身）加上 LLVM 自己变快，第一次没有附加条件。
以前是「升 LLVM 要赌一把」，现在升级的默认预期变成了正向。 @nikic / Make LLVM fast again
06 · 构建 / Cargo Rust Compiler · 2026

构建这一侧，能摸到的变多了

这几件事不改语言，但你每天都会碰到。

B1
cargo check 与 cargo build 共享缓存
@blyxyas 的项目目标。目标本身比名字更宽，但「check 过的东西 build 能直接用」是最好认的那个结果。
B2
no-embed-metadata 默认开启
已公布的改动：target 目录体积下降 5–30%，视工作负载而定。
B3
新的 build-dir 布局
又是那种「大改内部结构、顺手解锁别的东西」的活：细粒度锁 target 目录、跨 workspace 缓存。
B4
no-link / link-only
@bjorn3 在修这两个 flag 的支持，让 build script 和 proc macro 可以流水线化。同样是先修一长串内部问题，然后突然解锁一大块。
