# html-ppt：文章 → 幻灯片

## 步骤

### 第一步：分析文章

通读全文，提取：
- **标题**、**副标题**（如有，或根据导语提炼一句）、**作者**、**日期**（如果文章里有）
- **语言**：统一使用中文（`<html lang="zh-CN">`）——如果原文非中文，需要在生成时<strong>翻译为中文</strong>
- **标签/关键词**（3-4 个，用于标题页 `.meta` 的视觉平衡）
- **章节列表**：每个章节命名并标注**内容类型**：
  - `prose` — 纯文字论述
  - `code` — 含代码示例
  - `data` — 数值/统计
  - `list` — 列举/分类
  - `callout` — 关键结论

**完成标准：** 文章拆分为命名章节，每章标注内容类型，无遗漏。

---

### 第二步：分页

html-ppt 的页面结构固定：

| 页码 | 用途 | 组件 |
|------|------|------|
| 0 | 标题页 | `.slide-title` |
| 1…N-1 | 内容页，每章一页 | `.slide-content` |
| N | 总结页 | `.slide-content` + `.summary-grid` |

- **第 0 页：** 标题、副标题、作者、日期、标签
- **第 1…N-1 页：** 一页一个章节。章节过长时拆为连续两页，加"(续)"
- **第 N 页：** 提炼全文核心要点

**完成标准：** 每个章节分配到一页，顺序与原文一致，无遗漏、无合并。

---

### 第三步：生成 HTML

1. 从 [`light-template.html`](light-template.html) 复制 CSS 和 JS 样板
2. CSS 变量值保持与模板逐字一致
3. 根据第一步的内容类型，从 [`COMPONENTS.md`](COMPONENTS.md) 的映射表和 HTML 模式中选用组件
4. 导航栏 JS 和 HTML 从模板原样复制
5. 输出为单个自包含 HTML 文件（外部依赖仅 Highlight.js CDN）

**页面编号：** 每个 `.slide` 含 `data-index`，从 0 连续递增。

**内容提炼：**
- `.desc` 控制在 1-2 句
- 代码块选取关键片段（5-15 行），长行通过换行而非滚动展示
- `.highlight-box` 提炼为一句话结论
- 数值用逗号千分位

**视觉增强：**
- 每页的 `.section-label`、`h2`、`.cat-name`、`h4` 用 emoji 前缀点缀（如 📖 🔍 ⚡ 🎯），提升页面视觉吸引力
- `.section-label` 控制在 8 个字符以内（模板风格是短词，如「背景」「起点」）
- 可用行内样式 `<div style="...">` 构建简单数据流图或 lane 示意图，展示算法变换过程——但仅在原文有此内容且清晰度收益明显时才用

**完成标准：** 所有组件类名出自 COMPONENTS.md 词汇表，CSS 变量值与模板一致，data-index 连续。

---

### 第四步：验证

逐项检查：

- [ ] HTML 标签闭合、引号配对
- [ ] 每页 `.slide` 有 `data-index`，从 0 连续
- [ ] 第 0 页使用 `.slide-title`，其余页使用 `.slide-content`
- [ ] 代码块 `<code>` 标注了语言 class（`language-xxx`；通用文本可用 `language-text`）
- [ ] 代码块行号正常显示（模板 JS 已集成 `initLineNumbersOnLoad`）
- [ ] `<html lang="zh-CN">` 固定使用中文
- [ ] `.navigation-bar` 存在，含 prev/dot/next
- [ ] CSS 变量值与模板 `:root` 块逐字一致
- [ ] Highlight.js CDN 引用保留

**完成标准：** 全部检查项通过。

---

### 第五步：生成讲解文稿

为每页幻灯片写一段中文讲解词（旁白稿），保存为同目录下的 `*-script.md` 文件。

格式：

```markdown
# [文章标题] · 讲解稿

## 第 0 页 · [标题页标题]
[一段话讲解，约 3-5 句，简述本页要点和过渡逻辑，如果内容特别重要，可以扩展到8句话以内。]

## 第 1 页 · [内容页标题]
[一段话讲解]

...每页一段，直到最后一页...
```

**写作准则：**
- 每页一段，`##` 标题包含页码和页面标题
- 讲解词要口语化，适合演讲时朗读
- 段落开头自然承接上一页，结尾引出下一页（"接下来我们看..."）
- 代码页的讲解重点解释算法思路，不用逐行读代码
- 数据页的讲解突出数字含义和结论

**完成标准：** 每页都有一段讲解词，页数对应 `data-index` 一致，全文通读连贯。

---

### 第六步：截图输出

使用 `html-screenshot` 工具将每页幻灯片转为 PNG 图片。

```bash
html-screenshot -o [输出目录] -r 1080 -p slide [html 文件路径]
```

- `-o`：输出目录，默认为当前目录下新建 `slides/` 文件夹
- `-r 1080`：分辨率 1080（宽度 1920px，高度按比例）
- `-p slide`：输出文件名前缀为 `slide-1.png`、`slide-2.png`…

**完成标准：** 每页幻灯片生成一张 PNG 图片，页数与幻灯片数量一致，图片清晰可读。

---

## 约束

1. CSS 变量块与模板逐字一致
2. CSS 类名取自 COMPONENTS.md 词汇表
3. 导航栏的 JS 和 HTML 从模板原样复制
4. 输出为单个 HTML 文件
5. 响应式断点从模板原样保留
6. 每页 `.slide` 含 `data-index`，从 0 连续
7. 外部资源仅限 Highlight.js CDN 及其行号插件（`highlightjs-line-numbers`）
8. 行内视觉元素（简易 `div` 示意图）只许用 `style` 属性，不许引入新的 CSS 规则

---

## 失败模式

- **提前完成：** 页面太少或内容单薄 → 检查第二步是否真的每章一页。如果完成标准「每个章节都被分配」无法检验，说明章节划分本身不彻底。
- **样式漂移：** 颜色或字体走样 → 用 diff 对比输出文件的 `:root` 块与模板是否逐字一致。
- **组件混用：** 内容格式不对（如表格被当成列表） → 逐页对 COMPONENTS.md 中该内容类型的 HTML 模式，检查所用组件。
- **信息过载：** 单页内容过多 → 章节拆分不充分，将过长章节拆为连续两页。
