# html-ppt：文章/网页 → 幻灯片

## 步骤

### 第零步：获取内容

判断输入来源：
- **本地文本/Markdown**：直接进入第一步
- **网页链接**：使用 `fetch_content` 抓取网页全文，提取正文内容后进入第一步

**网页图片处理：**
1. 抓取网页时，识别正文中的 `<img>` 标签，记录每张图片的 URL、alt 文本、所在章节
2. 筛选**有内容价值的插图**（排除广告、图标、头像、装饰性小图），保留 3-8 张最能代表文章核心内容的图片
3. 将筛选后的图片下载到输出目录的 `images/` 子文件夹，文件名用序号命名（`img-01.jpg`、`img-02.png`…）
4. 下载时使用完整 URL（补全相对路径），设置合理的 User-Agent 和超时
5. 记录每张图片与章节的对应关系，供第二步分页和第三步生成 HTML 时使用
6. 如果下载失败（超时、403 等），尝试使用 SOCKS5 代理 `127.0.0.1:1084` 重试

**完成标准：** 输入内容已提取为纯文本；如有网页图片，已下载到 `images/` 目录并建立图片-章节映射表。

---

### 第一步：分析文章

通读全文，提取：
- **标题**、**副标题**（如有，或根据导语提炼一句）、**作者**、**日期**（如果文章里有）
- **语言**：统一使用中文（`<html lang="zh-CN">`）——如果原文非中文，需要在生成时<strong>翻译为中文</strong>
- **标签/关键词**（3-4 个，用于标题页 `.meta` 的视觉平衡）
- **章节列表**：每个章节命名并标注**内容类型**：
  - `prose` — 纯文字论述
  - `code` — 含代码示例
  - `data` — 数值/统计
  - `list` — 列举/分类
  - `callout` — 关键结论
  - `image` — 含配图（来自网页插图）

**完成标准：** 文章拆分为命名章节，每章标注内容类型，无遗漏；有图片的章节标注 `image` 类型。

---

### 第二步：分页

html-ppt 的页面结构固定：

| 页码 | 用途 | 组件 |
|------|------|------|
| 0 | 标题页 | `.slide-title` |
| 1…N-1 | 内容页，每章一页 | `.slide-content` |
| N | 总结页 | `.slide-content` + `.summary-grid` |

- **第 0 页：** 标题、副标题、作者、日期、标签
- **第 1…N-1 页：** 一页一个章节。章节过长时拆为连续两页，加"(续)"。含图片的章节优先分配图片，图片与文字上下排列。分页时预估每页内容量：代码 + 图片同页时内容易超标，提前规划（拆页或横向布局，见第三步「高度与横向布局」）
- **第 N 页：** 提炼全文核心要点

**完成标准：** 每个章节分配到一页，顺序与原文一致，无遗漏、无合并。

---

### 第三步：生成 HTML

1. 从 [`light-template.html`](light-template.html) 复制 CSS 和 JS 样板
2. CSS 变量值保持与模板逐字一致
3. 根据第一步的内容类型，从 [`COMPONENTS.md`](COMPONENTS.md) 的映射表和 HTML 模式中选用组件
4. 导航栏 JS 和 HTML 从模板原样复制
5. 输出为单个自包含 HTML 文件（外部依赖仅 Highlight.js CDN）

**页面编号：** 每个 `.slide` 含 `data-index`，从 0 连续递增。

**内容提炼：**
- `.desc` 控制在 1-2 句
- 代码块选取关键片段（5-15 行），长行通过换行而非滚动展示
- `.highlight-box` 提炼为一句话结论
- 数值用逗号千分位

**视觉增强：**
- 每页的 `.section-label`、`h2`、`.cat-name`、`h4` 用 emoji 前缀点缀（如 📖 🔍 ⚡ 🎯），提升页面视觉吸引力
- `.section-label` 控制在 8 个字符以内（模板风格是短词，如「背景」「起点」）
- 可用行内样式 `<div style="...">` 构建简单数据流图或 lane 示意图，展示算法变换过程——但仅在原文有此内容且清晰度收益明显时才用

**图片嵌入：**
- 内容类型为 `image` 的章节，使用 `.slide-image` 组件嵌入下载的图片
- 图片路径使用相对路径 `images/img-XX.ext`
- 每页最多放一张主图，图片等比缩放（`max-width:100%`、`max-height:360px`、`object-fit:contain`），绝不裁剪内容
- 图片下方用 `<p class="image-caption">` 标注图片说明（取自 alt 文本或原文图注）
- 图片与文字上下排列：文字在上，图片在下；或图片在上，文字在下——根据内容逻辑选择

**高度与横向布局：**
- **高度优先**：电脑屏幕宽度大于高度，幻灯片必须保持横版（页面宽 > 高）。布局视口以 960px 为准（模板 `.presentation-container` 的 `max-width`）：页面高度超过 960px 即变为竖版，是硬底线；理想高度 540–640px（接近 16:9）
- **纵向优先**：页面默认纵向排布（文字在上、图片在下）。宽高比大于 1:1（已横版）的页面不需要横向布局，不要为横向而横向
- **横向布局的适用条件**：仅当某页内容纵向排布会超高（页面高 > 宽，宽高比 ≤ 1:1）时，才把代码块和图片改为左右并排
- **并排写法**：用行内样式 flex 容器，`align-items` 必须用 `center`（垂直居中对齐，不是顶部对齐）：
  `<div style="display:flex;gap:18px;align-items:center;margin:4px 0;">`
- **栏宽分配**：代码栏 `flex:1 1 58%`（55–62%），图片栏 `flex:1 1 42%`（38–45%），两栏都加 `min-width:0` 防止撑破
- **压缩高度的手段**（按优先级）：精简代码到 5–15 行、缩短 `.desc` 到 1–2 句、调小图片 `max-height` 上限、把 `.highlight-box` 移入侧栏（图下方）而非全宽
- 并排时图片受栏宽约束会变小（等比缩放不裁剪），这是正常代价；宽图（宽高比 > 2:1）在窄栏中会很小，慎用并排

**完成标准：** 所有组件类名出自 COMPONENTS.md 词汇表，CSS 变量值与模板一致，data-index 连续。

---

### 第四步：验证

逐项检查：

- [ ] HTML 标签闭合、引号配对
- [ ] 每页 `.slide` 有 `data-index`，从 0 连续
- [ ] 第 0 页使用 `.slide-title`，其余页使用 `.slide-content`
- [ ] 代码块 `<code>` 标注了语言 class（`language-xxx`；通用文本可用 `language-text`）
- [ ] 代码块行号正常显示（模板 JS 已集成 `initLineNumbersOnLoad`）
- [ ] `<html lang="zh-CN">` 固定使用中文
- [ ] `.navigation-bar` 存在，含 prev/dot/next
- [ ] CSS 变量值与模板 `:root` 块逐字一致
- [ ] Highlight.js CDN 引用保留
- [ ] 页面高度量化检查：以 960px 布局视口用真实浏览器（如 playwright）逐页测量 `.slide` 高度，全部 < 960px（横版底线），尽量 ≤ 640px
- [ ] 横向布局的页面（如有）：flex 容器 `align-items:center` 垂直居中，两栏 `min-width:0`

**完成标准：** 全部检查项通过。

### 第五步：生成讲解文稿

为每页幻灯片写一段中文讲解词（旁白稿），保存为同目录下的 `*-script.md` 文件。

格式：

```markdown
# [文章标题] · 讲解稿

## 第 0 页 · [标题页标题]
[一段话讲解，约 3-5 句，简述本页要点和过渡逻辑，如果内容特别重要，可以扩展到8句话以内。]

## 第 1 页 · [内容页标题]
[一段话讲解]

...每页一段，直到最后一页...
```

**写作准则：**
- 每页一段，`##` 标题包含页码和页面标题
- 讲解词要**专业**，兼顾口语流畅与术语准确——像行业专家在技术分享会上讲解，而非照本宣科
- 段落开头自然承接上一页，结尾引出下一页（"接下来我们看..."）
- 代码页的讲解重点解释算法思路，不用逐行读代码
- 数据页的讲解突出数字含义和结论
- **延伸介绍**：对关键概念、技术背景、行业影响做适度展开——不局限于原文内容，补充必要的上下文知识（如技术演进脉络、相关标准/协议、实际应用场景），让听众获得比原文更深的理解
- 图片页的讲解要描述图片内容，解释图片与文字论述的关联，点出图片揭示的关键信息
- 避免空洞的过渡句（"下面我们来看下一页"），用内容本身驱动衔接
- **不使用破折号（——）**：讲解词是口语旁白，破折号会造成停顿突兀、断句生硬。改用逗号、冒号、句号重组句子，或用「即」「也就是」等词衔接；标题和正文中同样避免

**完成标准：** 每页都有一段讲解词，页数对应 `data-index` 一致，全文通读连贯；讲解词包含专业术语和延伸内容，非简单复述原文；全文不含破折号（——）。

---

### 第六步：截图输出

使用 `html-screenshot` 工具将每页幻灯片转为 PNG 图片。

```bash
html-screenshot -o [输出目录] -r 1080 -p slide [html 文件路径]
```

- `-o`：输出目录，默认为当前目录下新建 `slides/` 文件夹
- `-r 1080`：分辨率 1080（宽度 1920px，高度按比例）
- `-p slide`：输出文件名前缀为 `slide-1.png`、`slide-2.png`…
- 量化验证以真实浏览器测量为准：`html-screenshot` 的渲染结果可能与设计视口（960px）有偏差。若输出异常（页面异常变高、竖版、布局错乱），改用 playwright 等可控视口工具截图：视口 1008px（960px 内容 + 48px body padding）+ `deviceScaleFactor: 2`，逐页截 `.slide` 元素 → 1920px 宽输出，与 `html-screenshot` 格式一致

**完成标准：** 每页幻灯片生成一张 PNG 图片，页数与幻灯片数量一致，图片清晰可读。

## 约束

1. CSS 变量块与模板逐字一致
2. CSS 类名取自 COMPONENTS.md 词汇表
3. 导航栏的 JS 和 HTML 从模板原样复制
4. 输出为单个 HTML 文件
5. 响应式断点从模板原样保留
6. 每页 `.slide` 含 `data-index`，从 0 连续
7. 外部资源仅限 Highlight.js CDN 及其行号插件（`highlightjs-line-numbers`）
8. 行内视觉元素（简易 `div` 示意图）只许用 `style` 属性，不许引入新的 CSS 规则
9. 图片文件存放在 HTML 同级的 `images/` 目录，使用相对路径引用
10. 图片仅限从网页文章正文中提取的有内容价值的插图，排除装饰性图片
11. 讲解文稿（`*-script.md`）中不使用破折号（——）
12. 页面必须保持横版（宽 > 高）：960px 布局视口下 `.slide` 高度 < 960px，尽量 ≤ 640px
13. 横向（并排）布局仅用于纵向会超高（宽高比 ≤ 1:1）的页面，且 flex 容器必须 `align-items:center` 垂直居中

## 失败模式

- **提前完成：** 页面太少或内容单薄 → 检查第二步是否真的每章一页。如果完成标准「每个章节都被分配」无法检验，说明章节划分本身不彻底。
- **样式漂移：** 颜色或字体走样 → 用 diff 对比输出文件的 `:root` 块与模板是否逐字一致。
- **组件混用：** 内容格式不对（如表格被当成列表） → 逐页对 COMPONENTS.md 中该内容类型的 HTML 模式，检查所用组件。
- **信息过载：** 单页内容过多 → 章节拆分不充分，将过长章节拆为连续两页。
- **图片缺失：** 网页有插图但 PPT 中无图 → 检查第零步图片下载是否成功，图片路径是否正确，`images/` 目录是否与 HTML 同级。
- **图片裁剪：** 图片内容被截断 → `.slide-image img` 必须使用 `object-fit: contain`（不是 cover），`max-height` 仅作上限约束，图片等比缩放不裁切。若布局仍撑破，优先调大 max-height 而非裁剪图片。
- **页面过高/竖版：** 页面高度接近或超过宽度（宽高比 ≤ 1:1）→ 精简内容（代码、desc、图片 max-height）或对代码 + 图片采用横向布局；用真实浏览器量化测量高度，不要凭估算。
- **并排顶部对齐：** 横向布局的代码和图片顶部对齐、参差不齐 → flex 容器必须 `align-items:center` 垂直居中。
