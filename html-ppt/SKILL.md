# html-ppt：文章/网页 → 幻灯片

两套模板，按文章内容选一套，**不要混用**：

| 模板 | 适用文章 | 产出 | 画框 |
|---|---|---|---|
| [`article-template/index.html`](article-template/index.html) | 非代码文章：观点、叙事、案例、行业分析、数据图表。代码只作行内提及 | 单个自包含 HTML | 960×540，底部导航栏 |
| [`coding-template.html`](coding-template.html) | 代码密集文章：有大量代码例子、API、配置，抽掉代码论点就不成立 | 单个自包含 HTML | 960×540，底部导航栏 |

**选型规则：**
- 可展示代码 ≥ 3 段，或核心论点靠代码 / API / 配置支撑 → 代码模板
- 其余一律走非代码模板，包括只提几个函数名、字段名的文章
- 同一篇 deck 只用一套视觉系统，不允许两种模板的组件互相串门

---

## 输出结构

一篇 deck 一个目录，目录名用 URL 派生的 slug（如 `01-blog-cloudflare-com-rust-workers-emscripten-target`）：

```text
<slug>/
├── index.html      # 自包含幻灯片
├── script.md       # 逐页口播稿
├── slides/         # slide-1.png … 数量与页数一致
├── images/         # 正文配图 img-01.ext…（无图不建）
└── url             # 原文 URL，一行
```

批量模式下目录名带两位序号前缀，保留 `url` 文件以便回溯原文。

## 脚本

`scripts/` 里四个工具，除 playwright 外无依赖：

| 脚本 | 用途 | 命令 |
|---|---|---|
| `scripts/verify.js` | 验收：画框尺寸、溢出、顶栏页脚、data-index、代码块外壳、截图数、讲解稿页码 | `NODE_PATH=$(npm root -g) node <skill>/scripts/verify.js <目录>` |
| `scripts/shot.js` | 逐页截图，输出 1920×1080 | `NODE_PATH=$(npm root -g) node <skill>/scripts/shot.js <目录>` |
| `scripts/done.py` | 批量模式：从队列文件原子删除已完成的 URL | `python3 <skill>/scripts/done.py urls.txt <url>` |
| `scripts/batch.workflow.js` | 批量流水线（prux SubagentWorkflow） | 见「批量模式」 |

`NODE_PATH=$(npm root -g)` 让脚本找到全局安装的 playwright。

`verify.js` 输出 JSON `{ok, pages, errors, warns}`，退出码 0 才算通过：

- `--no-shots`：只验版面，跳过截图与讲解稿
- `--min N` / `--max N`：改页数下限 / 上限（默认 8 / 14）

## 第零步：获取内容

判断输入来源：
- **本地文本 / Markdown**：直接进入第一步
- **网页链接**：用 `fetch_content` 抓取全文，提取正文后进入第一步

**网页图片处理：**
1. 抓取时识别正文中的 `<img>`，记录每张图的 URL、alt 文本、所在章节
2. 筛选**有内容价值的插图**（排除广告、图标、头像、装饰性小图），保留 3–8 张
3. 下载到输出目录的 `images/`，按序号命名（`img-01.jpg`、`img-02.png`…）
4. 下载用完整 URL（补全相对路径），带合理 User-Agent 与超时
5. 记录每张图与章节的对应关系，供分页和生成 HTML 使用
6. 下载失败先试 SOCKS5 代理 `127.0.0.1:1084`；仍失败再用 `NODE_PATH=$(npm root -g) node fetch2.js "目标URL" "保存位置"` 抓网页（`fetch2.js` 不用于图片），给 30 秒超时

**完成标准：** 输入已转为纯文本；有图片时已落到 `images/` 并建立图片-章节映射表。

## 第一步：分析文章

通读全文，提取：
- **标题**、**副标题**（没有就从导语提炼一句）、**作者**、**日期**
- **语言**：统一中文（`<html lang="zh-CN">`）；原文非中文则翻译后再生成
- **标签/关键词**：3–4 个
- **章节列表**：每章命名并标注内容类型
  - `prose` 纯文字论述
  - `quote` 引语 / 观点句
  - `data` 数值 / 统计
  - `list` 列举 / 分类
  - `callout` 关键结论
  - `chart` 趋势 / 对比图
  - `image` 含配图
  - `code` 含代码示例（出现这个类型时，重新确认是否该用代码模板）

**完成标准：** 文章拆成命名章节，每章有内容类型，无遗漏。

## 第二步：分页

### A · 非代码文章（单文件）

固定画框 960×540。8–14 页，结构：

| 页码 | 用途 | 组件 |
|---|---|---|
| 0 | 标题页 | `.slide-title` |
| 1…N-1 | 内容页，每章一页 | `.slide-content` |
| N | 收尾 / 结论页 | `.slide-content` |

- 一页一章。章节过长拆为连续两页，标题加「（续）」
- 需要停顿或转折时可加引语页作为幕间；两幕结构最多一个幕间
- 每页一个 `.slide`，`data-index` 从 0 连续递增，顺序就是播放顺序
- 按「能不能撑满一页」切，不按段落数切；内容不够就补数字、表格、引语或旁注

### B · 代码文章（单文件）

固定结构：

| 页码 | 用途 | 组件 |
|---|---|---|
| 0 | 标题页 | `.slide-title` |
| 1…N-1 | 内容页，每章一页 | `.slide-content` |
| N | 总结页 | `.slide-content` + `.summary-grid` |

- **第 0 页**：标题、副标题、作者、日期、关键词
- **第 1…N-1 页**：一页一章。章节过长拆为连续两页，标题加「（续）」。含图章节优先分配图片。代码 + 图片同页时提前预估高度，超标就拆页或改并排
- **第 N 页**：提炼全文 3–5 个核心要点
- 每页都要有顶栏、页脚和一句结论；画框固定 960×540，按「能不能填满一页」来切，不要按段落数切

**完成标准：** 每章都有归属页面，顺序与原文一致，无遗漏、无硬合并。

## 第三步：生成 HTML

### A · 非代码文章（单文件）

1. 复制 `article-template/index.html` 为输出 HTML
2. 保留 `:root`、基础版式 CSS、`.navigation-bar` 与底部 JS，只替换页面内容
3. 每页一个 `.slide`，`data-index` 从 0 连续；第 0 页加 `.slide-title`，其余加 `.slide-content`
4. 页面局部样式写在 `<style>` 里，用页面 id 作用域（`#p03 .row { … }`），避免串页
5. 标题页、正文页、图表页、引语页的骨架直接参考模板里的 10 个示例页
6. 图片路径用 `images/img-XX.ext`（与 HTML 同级），`object-fit:contain`

页面骨架：

```html
<div class="slide slide-content" id="p03" data-index="3">
  <div class="top">
    <span><span class="sec">03</span> · 章节名</span>
    <span>栏目 · 关键词</span>
  </div>
  <div class="rule"></div>

  <h2>页面主张，不写「概述」</h2>
  <p class="dek">一到两句，给标题补上下文。</p>

  <div class="body">
    <!-- 内容从 dek 下方开始，向下填满 -->
  </div>

  <div class="foot">
    <span>本页结论，一句说完。</span>
    <span class="en">SOURCE / KEYWORD</span>
  </div>
</div>
```

组件与版式细则查 [`ARTICLE-COMPONENTS.md`](ARTICLE-COMPONENTS.md)。

#### 非代码模板设计规范（照做，不要自由发挥）

- **画框固定**：960×540，内容区宽 870px（左右各 45px padding），顶部 35px，底部 29px。`.slide` 实测高度必须正好 540px
- **版面必须填满**：主体区用 `flex:1` 吃掉剩余高度。禁止半页空白，也不许把内容垂直悬在中间
- **单一强调色**：默认 `--signal` 信号橙，文字用 `--signal-text`（深橙）。需要换色时只在 `:root` 改这两个值各一次，全篇冻结；每页强调不超过 3 处，不引入第二色
- **层级靠字号与字重，不靠颜色**：标题墨黑、正文 `--soft`、标签 `--text-muted`；hairline 分割代替阴影卡片，内容区圆角一律 0
- **字号**（960 视口，2x 输出约翻倍）：`h1` 48px、`h2` 33px（`h2.big` 44px）、`.dek` 12px、正文 11–12px、`.foot` 10.5px、`.note` 9px、等宽标签 8–9.5px。**正文不小于 11px，标签不小于 8px**
- **数字对齐**：统计数字、图表标签、表格数字统一 `font-variant-numeric: tabular-nums`，千分位用逗号
- **emoji 克制**：默认不用；确有语义时一页最多 1 个
- **禁止 AI 默认味**：圆角卡片、内容投影、渐变、紫蓝配色、左彩条、01/02/03 编号三件套、logo 墙、编造数据与评价
- **中文排印**：中英文之间留一个空格；句读用全角标点；不使用破折号（——）
- **一页一个视觉主角**：行列表、数字组、图、引语，只选一个
- **横向排版不画竖线**：并排的文本块之间只用间距和留白分隔，禁止竖直分隔线；论点页、引语页、旁注、数字组同理，区隔靠字号与字重
- **不放代码块**：函数名、字段名用 `<span class="mono">` 行内标注。代码需要成块展示时，说明这篇该走代码模板

#### 图表与图片

- 图表只在原文确有数据或趋势时画，用内联 SVG。坐标轴、单位、口径必须有；不是实测就写「定性示意，非实测数值」
- 关键拐点用 `--signal` 标一个点或一条虚线，一页只标一个
- 不编造 y 轴数字。没有数据就画流程图、时间线或结构图
- 图片 `object-fit:contain`，绝不裁剪；每页最多一张主图，高度不超过 210px
- 图注在图上方，写这张图证明了什么，不写「示意图」
- 图片说明用 `.note`，紧贴图片

#### 导航

- 底部导航栏固定：`◀` + 圆点 + `▶`，样式与 JS 从模板原样复制
- 方向键 / 空格翻页；Home / End 跳首尾
- 不设概览页、不设 iframe、不写 manifest
- `.slide` 之外不要放第二套页面容器

### B · 代码文章（单文件）

1. 从 `coding-template.html` **整段复制** CSS、导航栏 HTML 和底部 JS
2. `:root` 变量块逐字保留（见 COMPONENTS.md 末尾）
3. 每页套 COMPONENTS.md 的「版面骨架」：`.top` + `.rule` + `h2` + `.dek` + `.body` + `.foot`，六个部件一个都不能少
4. 按内容类型从映射表选组件，填进 `.body`
5. 输出单个自包含 HTML（外部依赖只有 Highlight.js 与行号插件两个 JS，样式全部内置）
6. 每个 `.slide` 带 `data-index`，从 0 连续递增

#### 亮色设计规范（照做，不要自由发挥）

- **画框固定**：960×540，2x 输出正好 1920×1080。`.slide` 高度必须正好 540px；内容不够就把组件放大或补内容，内容超出就拆页
- **版面必须填满**：顶栏、hairline、页脚各占一条，`.body` 从 `.dek` 下方开始向下排，用 `flex:1` 吃掉剩余高度。**禁止半页空白**，也不许靠垂直居中把内容悬在中间
- **单一强调色**：`--accent` 靛蓝。每页强调不超过 3 处（一个数字、一个关键词、一条左边线）。不要引入第四种彩色
- **层级靠字号和字重，不靠颜色**：正文灰、标题墨、强调蓝；hairline 分割代替阴影卡片，圆角一律 0
- **字号**（960 视口，2x 输出约翻倍）：`h2` 2.06rem（≈66px）、正文与 `.dek` 0.72–0.78rem（≈24–28px）、代码 0.7rem、标签注释 0.56–0.62rem。不许比这更小
- **数字对齐**：统计数字、表格数字、代码里的单位统一 `font-variant-numeric: tabular-nums`，千分位用逗号
- **emoji 克制**：只在有语义时用（🛰️ 表示卫星、🦀 表示 Rust），一页最多 2 个；禁止每个 `h2`、每个 `.cat-name` 前面都挂一个
- **禁止 AI 默认味**：暖奶油底 + 陶土色点缀、紫渐变、左彩条圆角卡片、全大写小标签 + 01/02/03 编号三件套、Logo 墙、编造数据与评价
- **中文排印**：中英文之间留一个空格；句读用全角标点；不使用破折号（——）
- **一页一个视觉主角**：要么是代码块，要么是数字，要么是图。三个都要抢，就拆页

#### 内容提炼

- 每页 `.foot` 左侧写一句本页结论，右侧写来源或英文关键词，**不许留空**
- `.dek` 1–2 句，给 `h2` 补上下文；`h2` 写主张，不写「概述」「背景」
- `.highlight-box` 一句话结论，一页最多一个
- 数值用逗号千分位；百分比保留一位小数
- 没有足够内容撑满一页时，补一张表格、一组数字、一个 `.rows` 行列表或一条结论，而不是拉大留白
- 列表类内容优先用 `.rows`（key + 标题 + 说明），每行自带 hairline，天然填满内容区
- 只有原文确有流程/变换时才画行内示意图，且只用 `style` 属性

#### 代码块（重点）

代码块用 `.code-block` 外壳，结构见 COMPONENTS.md：

```html
<div class="code-block">
    <div class="code-head">
        <span class="code-dots" aria-hidden="true"><i></i><i></i><i></i></span>
        <span class="code-label">Rust · 核心代码</span>
    </div>
    <pre><code class="language-rust">…</code></pre>
</div>
```

- **必须标语言**：`language-rust` / `language-python` / `language-javascript` / `language-bash` / `language-text`（输出、伪代码、配置片段）
- **`.code-label` 写「语言 · 用途」**，等宽大写小字，全篇口径统一
- **5–14 行**，单行 ≤ 80 字符；长行主动换行，不靠横向滚动（模板是 `pre-wrap`，滚动条永远不会出现）
- 一页最多一个代码块；再配一个 `.highlight-box` 或一个表格，别叠第二个代码块
- **行号由 `highlightjs-line-numbers` 自动生成**，不手写行号；不要给 `<pre>` 加属性，也不要再引第三方高亮 CSS 主题（token 配色内置在模板里）
- **HTML 实体转义**：`<` → `&lt;`，`>` → `&gt;`，`&` → `&amp;`，`"` → `&quot;`
- **代码必须真实可运行**：不杜撰 API、属性名和返回值。发布前把每段示例补上最小上下文，用该语言的工具实编译/实跑（`rustc`/`cargo check`、`python -c`、`node -e`、`bash -n`），退出码 0 才算过。报错就改示例，不要改说法
- 删掉与论点无关的样板（import、错误处理），只留能说明问题的 5–14 行；省略处用 `// …` 一行带过，不整段留白

#### 图片嵌入

- `image` 类型章节用 `.slide-image` + `p.image-caption`
- 图片说明放在图片上方，紧贴图片
- 相对路径 `images/img-XX.ext`；每页最多一张主图
- `object-fit: contain` 等比缩放，绝不裁剪
- 图片最高 280px，超出会挤压 `.body`；代码与图同页时改用并排

#### 高度与横向布局

- **固定画框**：960×540。页面高度必须正好 540px，撑高就说明内容超了，拆页或改并排；不许缩字号硬塞
- **密度优先**：内容不足时补表格、数字、结论句，把 `.body` 填实；不许出现半页空白
- **并排写法**（代码 + 图片、代码 + 列表）：

  ```html
  <div style="display:grid;grid-template-columns:60% 1fr;gap:18px;align-items:stretch;">
      <div class="code-block">…</div>
      <div>
          <p class="image-caption">图 1：说明</p>
          <div class="slide-image"><img src="images/img-01.png" alt="…" /></div>
      </div>
  </div>
  ```

- **为什么不能用 flex**：flex 的 `align-items:center` 只居中整栏，栏内的标签、图片说明会把两个主块顶成顶部对齐。grid 的 `align-items:center` 让左右两栏中线重合
- **代码栏与右侧等高**：代码 + 列表并排时用 `align-items:stretch`，代码块会被拉到与右侧列表同高，不留上下空隙；代码 + 图片用 `align-items:center`
- **主块清零外边距**：并排时 `.code-block` 与 `.slide-image` 写 `margin:0`，间距交给 `gap`
- **栏宽 60% / 40%**：代码栏需要 80 字符宽度；宽图（宽高比 > 2:1）在窄栏里会很小，慎用并排
- **压缩顺序**：精简代码到 5–14 行 → 缩短 `.dek` → 调小图片 `max-height` → 改并排；不要靠缩字号

**完成标准（两种模板）：** 类名 / 原语全部出自对应文档，画框尺寸正确，每页横版，无溢出。

## 第四步：验证

先跑脚本拿硬指标，再对照下面的清单补人工检查项：

```bash
NODE_PATH=$(npm root -g) node ~/.prux/skills/html-ppt/scripts/verify.js <输出目录>
```

`ok: true`、`errors` 为空才算过；`warns` 逐条落实（尤其 `.body` 缺失、正文区偏矮、破折号）。截图与讲解稿还没生成时，先加 `--no-shots`。

### A · 非代码文章

- [ ] 输出单个 HTML，`<html lang="zh-CN">`，全文中文，无破折号
- [ ] 每页 `.slide` 实测 960×540，`scrollWidth` / `scrollHeight` 不超出
- [ ] 每页 `.slide` 有 `data-index`，从 0 连续；第 0 页 `.slide-title`，其余 `.slide-content`
- [ ] 每页 `.top` + `.rule` + `.foot` 齐全，顶栏与页脚左右都不为空
- [ ] 底部 `.navigation-bar` 存在，含 prev / dot / next，翻页正常
- [ ] 页面局部样式已用 id 作用域，未污染其他页面
- [ ] 每页只有一个视觉主角；主体内容至少占满内容区的三分之二
- [ ] 全篇单一强调色，每页强调 ≤ 3 处
- [ ] 字号达标：`h1` 48px、`h2` ≥ 33px、正文 ≥ 11px、标签 ≥ 8px
- [ ] 没有代码块、内容投影、圆角卡片、渐变、logo 墙、emoji 堆砌
- [ ] 横排文本块之间无竖直分隔线
- [ ] 图片路径 `images/…`，`object-fit:contain`，未裁剪
- [ ] 图表有坐标轴 / 单位 / 口径，或明确标注「定性示意」
- [ ] 所有数字与引语可追溯到原文，无杜撰
- [ ] 没有概览页、iframe、manifest

### B · 代码文章

- [ ] HTML 标签闭合、引号配对、实体已转义
- [ ] 每页 `.slide` 有 `data-index`，从 0 连续
- [ ] 第 0 页 `.slide-title`，其余全部 `.slide-content`
- [ ] 每页都有 `.top` + `.rule` + `.body` + `.foot`，页脚左右都不为空
- [ ] 每个代码块都有 `.code-block` 外壳、`.code-head`、`.code-dots`、`.code-label`
- [ ] 每个 `code` 都有 `language-xxx`；`language-text` 用于纯输出
- [ ] 页面上没有引入 `github.min.css` 等第三方高亮主题，token 配色来自模板
- [ ] 行号正常显示（`hljs-ln-numbers` 在 DOM 里出现），代码块无横向滚动条
- [ ] 字号达标：`h2` ≥ 2rem，正文与 `.dek` ≥ 0.72rem，代码 ≥ 0.7rem，标签 ≥ 0.56rem
- [ ] 每段代码用对应语言工具实编译/实跑通过，无杜撰 API
- [ ] `<html lang="zh-CN">`；全文中文
- [ ] `.navigation-bar` 存在，含 prev / dot / next
- [ ] `:root` 与模板逐字一致
- [ ] 每页强调色 ≤ 3 处；无 emoji 堆砌
- [ ] 逐页测量 `.slide` 高度：960px 视口下必须正好 540px（±1px），超出就是内容超载
- [ ] 每页 `.body` 不是半页空白：内容至少占满内容区的三分之二
- [ ] 并排页面左右两栏垂直中心 |Δ| ≤ 2px（量中心，不是量顶部）

**完成标准（两种模板）：** `verify.js` 返回 `ok: true`，且 errors 为空。

## 第五步：生成讲解文稿（口播稿）

为每页写一段中文讲解词，保存为同目录的 `script.md`。文件名固定，`verify.js` 按这个名字查页码范围。

**这是口播稿，写给耳朵听，不是写给眼睛看。** 每一段都要能直接念出来配到画面上。

### 听众假设

- 边听边看画面，注意力在耳朵上，漏掉一句不会回听，所以一页只讲一件事
- 看不见图表细枝末节，关键数字必须用嘴点出来，不能只说「如图所示」
- 一页 40 到 60 秒，全片 8 到 14 分钟，节奏靠句子长短控制，不靠停顿符号

### 人称与语气

- 讲者用「我」，听众用「你」，需要站同一侧时说「我们」
- 不用「本页」「该章节」「下面展示」这类文档用语，直接用内容指代
- 术语第一次出现必须带半句解释，解释放在术语后面，用逗号接
- 语气可以有起伏，允许「有意思的是」「麻烦就在这」这类判断句，但不煽情

### 句子

- 短句为主，一句一个信息点，超过 25 字就断开
- 允许口语碎片：「好」「那」「你看」「说白了」「注意这里」「反过来」
- 每页至少一个设问，自问自答推进，问题要真问，不要「那么问题来了」套话
- 数字口语化：先念成听的懂的量级，原文精确值随后补一句
  - 3750 万 → 「三千七百五十万，差不多三千八百万」
  - 61% → 「六成」；0.3% → 「千分之三，几乎可以忽略」

### 每段三段式

1. **进**：一句接住上一页，或者甩一个问题出来
2. **讲**：本页核心，两到四句，必须落到一个具体细节（数字、人名、场景、代码行为）
3. **出**：一句留钩子，把听众推到下一页

三段之间不空行，一段到底，念的时候一口气说完。

### 长度与节奏

| 页面 | 字数 | 时长 |
|---|---|---|
| 标题页（第 0 页） | 80 到 150 | 20 到 35 秒 |
| 常规内容页 | 120 到 200 | 30 到 50 秒 |
| 重点内容页 | 200 到 300 | 50 到 70 秒 |
| 总结页（末页） | 150 到 250 | 35 到 60 秒 |

按每分钟 250 字换算。任何一页超过 300 字，说明内容该拆页，不是稿子该加长。

### 首尾页写法

- **第 0 页**：先打招呼，再抛全文那个总问题，最后一句说清「听完你能拿到什么」。不要念标题、不要念作者单位和日期
- **末页**：收束三到五个要点，每点一句，回扣第 0 页抛的问题，最后留一句能被带走的判断

### 示例

坏（文档腔，不能念）：

```markdown
## 第 3 页 · 成本结构变化
本页展示了成本结构的变化趋势。如图所示，算力成本占比从 2020 年的 42% 上升到 2023 年的 61%，值得注意的是，这一变化反映了行业的整体转向。
```

好（口播腔，能直接念）：

```markdown
## 第 3 页 · 成本结构变了
上一页我们说到，模型能力已经不是瓶颈了。那瓶颈在哪？看这张图。三年前，算力只占成本的四成出头，现在呢，六成。也就是说，你多花一块钱，有六毛是交给机器的。这不是省钱的问题，是整个生意的算法变了。
```

### 避坑

- **念稿腔**：删掉「本页我们来看」「如图所示」「综上所述」「值得注意的是」「不难发现」「由此可见」
- 不念页码、不念页面标题、不念导航栏和按钮
- 连续三页用同一个开场句式（「接下来」「然后」「下面」）就重写
- 不解释版面怎么排、颜色怎么选，只讲内容本身
- 不写「这一页很重要」「这里特别关键」这类自我评价，重要就讲透
- 不用破折号，停顿靠句号、逗号和短句，需要转折用「但」「不过」「问题是」
- 一页最多两个新术语，第三个就换成大白话
- 图片页用嘴描述图里有什么、它证明了什么，不写「请看图 1」
- 代码页讲这段代码想解决什么、跑起来会发生什么，不逐行念语法

**页码对应：** 两套模板都从 0 开始，讲解稿第 N 页对应 `data-index="N"` 的页面。

**完成标准：** 每页都有讲解词，页码与 deck 顺序对应；出声念一遍每页落在上表时长区间；无破折号；无「本页 / 如图所示 / 综上所述 / 值得注意的是」等念稿腔词。

## 第六步：截图输出

### 两套模板通用

默认用 `scripts/shot.js`，视口可控、输出稳定：

```bash
NODE_PATH=$(npm root -g) node ~/.prux/skills/html-ppt/scripts/shot.js <输出目录>
```

- 视口 1008px（960 内容 + 48 body padding），`deviceScaleFactor: 2`，逐页截 `.slide`
- 输出 `<目录>/slides/slide-1.png`、`slide-2.png`…，正好 1920×1080
- `--prefix <名字>` 改文件名前缀

也可以用 `html-screenshot`：

```bash
html-screenshot -o [输出目录] -r 1080 -p slide [html 文件路径]
```

- `-r 1080`：宽度 1920px，高度按比例
- html-screenshot 的渲染结果可能与 960px 设计视口有偏差，输出异常（页面异常变高、竖版、布局错乱）时改用 `scripts/shot.js`

出图后再跑一次完整验收：

```bash
NODE_PATH=$(npm root -g) node ~/.prux/skills/html-ppt/scripts/verify.js <输出目录>
```

`verify.js` 会比对 `.slide` 数量与 PNG 数量，并检查 `script.md` 是否覆盖每一页。

**完成标准：** `verify.js` 返回 `ok: true`；每页一张 PNG，数量与 `.slide` 数量一致，图片清晰可读。

## 约束

### 通用

1. 输出语言统一中文，`<html lang="zh-CN">`

3. 图片仅限正文中有内容价值的插图，排除装饰图
4. 不编造数据、引语、API 与评价
5. 同一篇 deck 只用一套模板，不混用视觉系统

### A · 非代码文章

6. 输出单个自包含 HTML，导航栏 HTML 与 JS 从模板原样复制
7. `:root` 与基础版式不改，页面差异用页面 id 作用域的局部 `<style>`
8. 画框固定 960×540，内容溢出就拆页
9. 每页 `.slide` 含 `data-index`，从 0 连续
10. 每页 `.top` / `.rule` / `.foot` 齐全，两侧都有内容
11. 全篇单一强调色，每页强调 ≤ 3 处
12. 不写代码块；专名用 `.mono` 行内标注
13. 图片路径 `images/…`，`object-fit:contain`
14. 图表必须有出处；非实测就标「定性示意」
15. 不设概览页、iframe、manifest

### B · 代码文章

16. `:root` 变量块与模板逐字一致
17. 类名取自 COMPONENTS.md 词汇表，不自创组件
18. 导航栏 HTML 与 JS 从模板原样复制
19. 输出为单个 HTML 文件
20. 响应式断点从模板原样保留
21. 每个 `.slide` 含 `data-index`，从 0 连续
22. 外部资源仅限 Highlight.js 与其行号插件的 JS；高亮配色内置，不引第三方主题 CSS
23. 行内视觉元素只许用 `style` 属性，不新增 CSS 规则
24. 图片放在 HTML 同级的 `images/`，用相对路径
25. 画框固定：960px 视口下 `.slide` 高度必须正好 540px，超出就拆页

28. 每页 `.top` / `.rule` / `.body` / `.foot` 四件齐全，页脚两侧都有内容
29. 不要读取已下载图片或截图中的内容

## 批量模式

多条 URL 时，每条一个目录 + 一个队列文件，不要把它们塞进同一份 deck。

1. 从 `urls.txt` 建目录（两位序号 + URL slug），把 URL 写进各自的 `url` 文件
2. 用 [`scripts/batch.workflow.js`](scripts/batch.workflow.js) 跑流水线：第一段生成，第二段截图 + 按 `verify.js` 修到全绿
3. 每条通过后 `gate` 自动调 `scripts/done.py` 把该 URL 从 `urls.txt` 删除，队列文件就是进度条

```js
SubagentWorkflow({
  scriptPath: '~/.prux/skills/html-ppt/scripts/batch.workflow.js',
  args: {
    base: '/绝对/输出根目录',
    queue: 'urls.txt',                       // 可省略；给了就自动删已完成项
    items: [{ url: 'https://…', dir: '01-xxx' }],
  },
})
```

- 并发由运行时控制（通常 16 路），不要手写循环逐条等
- 抓不到正文的 URL（登录页、OAuth 回调、404）不硬编内容：目录里只留 `url` 和 `NOTE.md`，保留在队列里等人工处理
- 单条 `verify.js` 失败不会污染其他条：失败项自己留着，队列里不删

## 失败模式

- **脚本报 FAIL**：按 `errors` 逐条改版面，不要改脚本、不要删检查项；`warns` 也不能长期挂着
- **模板选错**：非代码文章里塞了三个代码块 → 改走代码模板；代码文章通篇没有代码 → 改走非代码模板
- **提前完成**：页数太少或内容单薄 → 回查第二步，确认每章真的分到页面
- **非代码页变成网页**：出现圆角卡片、阴影、渐变、彩色图标 → 删掉，回到 hairline + 字号层级
- **非代码页撑出画框**：960×540 下出现滚动 → 精简文案、缩小图片、减少一行列表，不许缩字号
- **页面串样式**：局部 CSS 没有按页面 id 作用域，上一页的 `.row` / `.note` 影响下一页 → 所有页面局部选择器加 `#pNN` 前缀
- **html-screenshot 少页**：`.slide` 数量与 `data-index` 不一致，或有页面藏在 iframe 里 → 每页必须是直接子元素，`data-index` 从 0 连续
- **图片 404**：图片没有放在 HTML 同级的 `images/`，或路径写成了绝对路径 → 改成 `images/img-XX.ext`
- **样式漂移**：颜色/字体走样 → 用 diff 对比输出与模板的 `:root` 块
- **亮色变灰**：页面看起来像网页而不是幻灯片 → 检查是否引了 `github.min.css`、是否把底色改成了纯灰 `#f5f5f5`、是否把字号降到了 `0.75rem` 以下
- **代码块像正文**：没有外壳、没有语言标签、字号过小、行号缺失 → 按第三步「代码块」逐项对照 COMPONENTS.md
- **代码跑不起来**：复制出去就报 `Unknown property` / `NameError` → 示例必须实编译实跑；报错就改代码，别改说法
- **组件混用**：表格被当列表、代码被当正文 → 逐页对 COMPONENTS.md 中该内容类型的 HTML 模式
- **信息过载**：单页内容过多 → 拆页，不要缩字号
- **emoji 堆砌**：每个标题、每个列表项都挂 emoji → 一页最多 2 个，只保留有语义的
- **图片缺失**：网页有插图但 PPT 无图 → 检查第零步下载与 `images/` 路径
- **图片裁剪**：内容被截断 → `object-fit: contain`，`max-height` 只是上限
- **半页空白**：内容挤在上半页、下半页空着 → 补表格/数字/结论，或把列表行距拉开；不允许靠调大 `min-height` 掩盖
- **页面撑出画框**：`.slide` 高度超出 → 精简代码、缩短 `.dek`、调小图片 `max-height`，或改并排；用浏览器量高度，不要估
- **并排中线不重合**：代码块与图片顶部齐平、中线错开 → 不要用 flex；用 grid 并排，主块 `margin:0`，量垂直中心而不是顶部
- **讲解稿念稿腔**：出现「本页我们来看」「如图所示」「综上所述」「值得注意的是」，或整段长句没有设问 → 按第五步「避坑」重写，出声念一遍再定稿
- **讲解稿时长失控**：单页超过 300 字、念下来超过 70 秒 → 拆页或砍到三段式之内，不要靠加快语速消化
